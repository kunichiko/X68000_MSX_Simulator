# About MS.X

This is MSX Simulator working on the X68000 series computers. I made it when I was teenager and it is just my study, so it is not completed.

But I decided to make it public for my memorial.

# How to use (in Japanese)

実行にはMC68030以上が必要です。Phantom Xをお使いの場合は、

```
> pxctl -e 3
→その後物理リセット
```

などでCPUを030仕様に変更してください。(ワード境界を跨ぐアクセスなどをしているためですが、将来修正するかもしれません)

また、Phantom Xはライトバックモードで動かさないと速度が出ませんので、以下のようにしてライトバックモードにしてください。

```
> pxctl -c b
```

## X68000実機へのインストール

本リポジトリの exe フォルダ以下を X68000実機に持っていってください。たとえば、A:¥MSX¥ にインストールする場合は以下のようになります。

```
A:¥
 ├── MSX
 │   ├── ms.x
 │   ├── ms.ini
 │   ├── msxroms
 │   │   ├── cbios_logo_msx1.rom
 │   │   ├── cbios_logo_msx2.rom
 │   │   ├── cbios_main_msx1_jp.rom
 │   │   ├── cbios_main_msx2_jp.rom
 │   │   ├── cbios_sub.rom
 │   │   ├── MSX.PAC
```

exeフォルダには以下のファイルもありますが、必ずしも必要ではありません。

* `ms_debug.x`
	* デバッグ用のバージョンです。F6キーでログレベルを上げることで、デバッグ情報が表示されるようになります。
	* Cコンパイラの最適化も無効化しているため、ソースコードレベルでバッグなどがしやすくなっています。
* `ms_debug.x.elf`, `ms.x.elf`
	* デバッグ用のELFファイルです。gdbserverを使ってソースコードレベルでデバッグする際に使用します


## 実行方法

インストールされた MS.Xにパスを通すなどして、`ms.x` を実行すると、MSXが起動します。

```
> ms.x
```

デフォルトの設定ファイル(`ms.ini`)は無償のBIOS ROMである CBIOSが指定されているので、起動ロゴなどは出ますが、BASICが利用できないため、それ以上何かをすることはできません。

たとえばゲームのROMイメージを起動したい場合は、以下のようにして起動してください。

```
> ms.x -r GAME.ROM
```

ROMの種類はある程度は自動判別します。現在サポートしているのは、

* 16KB ROM
* 32KB ROM
* メガロム (ASCII 8K方式)
* メガロム (コナミ SCCなし方式)
* メガロム (コナミ SCCあり方式。ただしSCCは鳴りません)
* ESE-RAM
* ESE-SCC

です。自動判別がうまくいかない場合は、ファイル名の後に `,<ROM種別>` をつけて強制的に指定することも可能です。

使えるROM種別は以下の通りです。

* MIR: 通常のミラードROM (16KB, 32KB) (page1,2に配置されるが、他のページにもミラー内容が見える)
* G8K: メガロム (GENERIC 8K方式)
* A8K: メガロム (ASCII 8K方式)
* A16: メガロム (ASCII 16K方式) (未実装)
* KON: メガロム (コナミ SCCなし方式)
* SCC: メガロム (コナミ SCCあり方式)
* ERAM: ESE-RAM
* ESCC: ESE-SCC

例:
```
> ms.x -r GAME.ROM,G8K
```


また、 `-r1` や `-r2` を使うと、アタッチするスロットを明示的に指定することが可能です。例えば、スロット1に [TINY SLOT CHECKER for MSX](https://www.tiny-yarou.com/slotchecker.html) の ROMをセットし、スロット2にゲームのROMをセットしたい場合は、以下のようにして起動します。

```
> ms.x -r1 TNSLCK.ROM -r2 GAME.ROM,NOR
```

なお、詳しくは ms.ini の節で説明しますが、以下のように起動設定ごとに細かくフォルダを用意することで、ゲームタイトルやMSXのROMバージョンなど、さまざまな環境を簡単に切り替えて実行することができます。

```
A:¥
 ├── MSXGAMES
 │   ├── GAME1
 │   │   ├── ms.ini
 │   │   ├── GAME1.ROM
 │   ├── GAME2
 │   │   ├── ms.ini
 │   │   ├── GAME2.ROM
 │   ├── GAME3
 │   │   ├── ms.ini
 │   │   ├── GAME3.ROM
```

たとえば `A:¥MSXGAMES¥GAME1¥ms.ini` には以下のような設定を行います。

```
cart1=GAME1.ROM
```

この状態で `A:¥MSXGAMES¥GAME1` 上で ms.x を起動すると、GAME1.ROM がカートリッジスロット1にセットされた状態で起動します。


### ROMデータベース

お持ちのROMがどのメガロムタイプかを判別するのは容易ではないのですが、[msx.orgのフォーラムの Vamplerさんの投稿](https://www.msx.org/forum/msx-talk/openmsx/openmsx-romdb-download) にリンクされている、[openMSX用 ROM DB (softwaredb)](https://romdb.vampier.net/archive.php) に、ROMのバイナリHASHとメガロムタイプの一覧がありますので、そちらが参考になります。zipファイルを解凍して出てくるXMLファイルを見れば、なんとなく雰囲気がわかるかと思います。

各ROMのタイトルの下に、以下のようなXMLが記述されています。

```
<dump><megarom><type>GenericKonami</type><hash>68691348a29ce59046f993e9abaf3c8651bdda3c</hash></megarom></dump>
```

お持ちのROMイメージのSHA1ハッシュが `68691348a29ce59046f993e9abaf3c8651bdda3c` であれば、このXMLから `GenericKonami` というメガロムタイプであることがわかります。

このタイプはどうやらかなりたくさんあるようで、おそらくこの辺りが一覧だと思います。
https://www.msxblue.com/manual/rommappers_c.htm

これら全てを対応しているわけではありませんので、ご了承ください。また呼び方がちょっと違うケースもあり、混乱しますが、今のところ、以下のような対応になっていると思います。

* ASCII8: ASCII 8K方式 `A8K`
* ASCII16: ASCII 16K方式 `A16` (未対応)
* GenericKonami: GENERIC 8K方式 `G8K`
* Konami: コナミ SCCなし方式 `KON`
* KonamiSCC: コナミ SCCあり方式 `SCC`

XMLの仕様については、以下を参照してください。
https://www.msxblue.com/manual/romdatabase.htm

将来的にはこのデータベースファイルを使って、ROMの自動判別を行うようにしたいです。

## BIOSの差し替え

C-BIOSではなく、実機のROMを使いたい場合は、自分でダンプするなどしてご用意ください。

* MAINROM.ROM - メインROM 32KB
* SUBROM.ROM - サブROM 16KB

の２つをご用意いただき、-rm、-rs オプションで指定してください。
常用する場合は、後述する `ms.ini` ファイルに書いておくと便利です。

```
> ms.x -r GAME.ROM -rm MY_MAINROM.ROM -rs MY_SUBROM.ROM
```

### 漢字ROMのサポート

ゲームによっては「要漢字ROM」というものがあり、これは漢字ROMが必要なゲームです。
MS.Xでは、漢字ROMの指定がない場合でも、自動的にX68000の16x16ドットフォントを使用した代替漢字ROMが有効になります(第二水準まで対応)。
もし実機の漢字ROMを使いたい場合は、以下のように -rk オプションで指定してください。

```
> ms.x -rk fs-a1f_kanjifont.rom
```

* 第一水準までの漢字ROMは 128KB
* 第二水準を持つ漢字ROMは 256KB

となります。

漢字ROMを無効化したい場合は --disablekanji オプションを指定してください。


## フロッピーディスクのサポート

MS.Xは フロッピーディスクコントローラーIC(FDC)をエミュレーションして、ディスクイメージファイル(*.2DD)もしくは9scdrvを使って実3.5インチドライブにアクセスすることができます。現在、以下の2種類のFDCに対応しています。

* **TC8566AF** (東芝) — 主に Panasonic系のMSXで使用 (デフォルト)
* **WD2793** (Western Digital) — SONY / Philips系のMSXで使用

しかし、MSXでフロッピーディスクを使用するためにはFDCに対応したDISK BIOSが必要です (C-BIOSでは対応できません)。使用するDISK BIOS ROMを吸い出した実機のFDCに合わせて、`diskif` オプション(後述)でFDCの種類を指定してください。

まずは Panasonic系(TC8566AF)の例です。それらの該当実機のDISK BIOSを抽出し、 `-rd` オプションで指定してください。例えば、FS-A1FのBIOSを使いたい場合は、以下のように指定します。

```
> ms.x -rm fs-a1f_basic-bios2.rom -rs fs-a1f_msx2sub.rom -rd fs-a1f_disk.rom DISKIMAGE1.DSK DISKIMAGE2.DSK
```

上記の通り、使用したいディスクイメージ(.DSK)も引数で指定しておいてください。最大15個まで指定できます。
ディスクの切り替えは `OPT.1` + [キー] キーで行うことができます。キーの組み泡汗は以下の通りです。

* `ESC` - イジェクト
* `0` - 9scdv (使用可能に設定している場合のみ)
* `1-9` - ディスクイメージ番号(1-9)
  *  数字キーはテンキーではなく、QWERTYの上の数字です
* `A-F` - ディスクイメージ番号(10-15)

後述する `ms.ini` ファイルを使い、以下のようにしておくと、いちいちオプションを指定しなくても良いため便利です。

```
mainrom=fs-a1f_basic-bios2.rom
subrom=fs-a1f_msx2sub.rom 
diskrom=fs-a1f_disk.rom
diskimage=DISKIMAGE1.DSK
```

### FDCの種類の指定

SONY(またはPhilips)系のMSXのDISK BIOS ROMを使う場合は、FDCが WD2793 になるため、
DISK ROM のファイル名の後ろに `,種類` を付けてFDCの種類を指定してください
(メガロムの種類指定と同じ方式です)。省略した場合は従来どおり TC8566AF (Panasonic系)
として動作します。

指定できる種類は以下のとおりです。これら以外の値を指定するとエラーになります。

* `panasonic` (または `tc8566af`) … TC8566AF (デフォルト。省略時もこれ)
* `sony` (または `philips` / `wd2793`) … WD2793

起動オプションでは以下のように `,sony` を付けて指定します。

```
> ms.x -rm sony_basic.rom -rs sony_sub.rom -rd sony_disk.rom,sony DISKIMAGE1.DSK
```

`ms.ini` でも同様に `diskrom` の値に `,sony` を付けます。

```
mainrom=sony_basic.rom
subrom=sony_sub.rom
diskrom=sony_disk.rom,sony
diskimage=DISKIMAGE1.DSK
```

> WD2793対応では、セクタ単位のREAD/WRITE(通常のディスクアクセス)とシークを優先して実装しています。
> フォーマット(Write Track)はベストエフォート対応です。また .DSK 形式はギャップ情報を保持しないため、
> プロテクトの再現はできません(これはTC8566AFと同じ制約です)。

9scdrvを使う場合は `--9scdrv` オプションか、 `ms.ini` の `9scdrv` パラメータでドライブID(0-3)を指定しておく必要があります。

```
> ms.x --9scdrv=2
```

```
mainrom=fs-a1f_basic-bios2.rom
subrom=fs-a1f_msx2sub.rom 
diskrom=fs-a1f_disk.rom
9scdrv=2
```

9scdrvとディスクイメージの併用も可能です。 `OPT1` + `0` で 9scdrvが選択され、 `OPT1` + [数字] キーでイメージファイルを選択可能です。


ファイルの書き換えやフォーマットもサポートしていますが、まだ不安定な可能性があります。また、9scdrvは実験的にREADのみ対応しています。
ディスクイメージが壊れる可能性もりますので、バックアップは十分に取っておくようにしてください。
なお、大事なディスクイメージは attrib コマンドや mintなどで読み取り専用属性をつけておけば、ライトプロテクト状態になりますので少し安全になります。

```
A>attrib +r DISKIMAGE1.DSK
```

## 実機のDISK ROMが使えない場合の回避策

MSXのDISK ROMは色々と権利関係の問題があり、実機から吸い出す以外の方法が無く、各エミュレータ苦労しているようです。
MS.Xでもそのうちなんとかしたいとは思っていますが、まだ実現はできていません。

回避策としては、 **DISKイメージをROM化するソフトを使う** という方法があります。私が調べた範囲だと以下のようなものがあります。

* [MKROMDSK](https://www.msx.org/news/software/en/mkromdsk)
	* こちらはどうも実機のDISK BIOSを内蔵しているというような話もあり、ライセンス的にちょっと危ない感じがします(私は試してません)
* [dsk2rom](https://github.com/joyrex2001/dsk2rom)
	* こちらもライセンスの怪しいコードが含まれているという話があります
* [TablacusDiskRomLite](https://github.com/tablacus/TablacusDiskRomLite)
	* 大本命です
	* 2024年現在もかなり精力的に開発がされており、どんどんサポートが増えているようです。
	* こちらはライセンス的な問題のない互換DISK ROMを使っているので、安心して使えます
	* ただ、ディスクは2枚までセットできるものの、AドライブとBドライブに破り当たってしまうため、Aドライブのファイルを入れ替えるタイプのゲームには対応できません

### TablacusDiskRomLiteの使い方

詳しくはリンク先のREADMEを参照していただきたいですが、MS.Xで使う場合の注意点を記載します。

まず、TablacusDiskRomLiteは、互換DISKROMの後ろに、動かしたいディスクイメージ(.DSK)を連結することでROM化しています。その際、使用する互換DISKROMには、以下のような種類があります。

* DISKROM.BIN
	* 8KBバンクメガロム対応のDISKROM
	* MSX1でも動くような省メモリ版(?)のようです
* DISKROM64K.BIN
	* 8KBバンクメガロム対応のDISKROMですが、64KBメモリに対応しているため、似非DOS(MSX-DOS互換のDOS)など、メモリを多く使うソフトにも対応しているようです
	* MSX2のゲームなどを動かす場合はこちらを使うのが良さそうです
* DISKROM32.BIN
	* 非メガロムの32KB未満のコントローラーを使う場合や、16KBバンクメガロムを使う場合のものです
* DISKROM64K32.BIN
	* DISKROM32.BINの64KB版です

TablacusDiskRomLiteは実際に物理的なROMカートリッジを作ることを想定しているので、使用するコントローラーの種類に合わせられるよう、上記のような複数のイメージを用意しているようです。

MS.Xの場合は8KBバンクメガロムを使えますので、**DISKROM64K.BIN を使い、ASCII 8KタイプのメガロムとしてロードすればOKです。**

ファイルの連結方法は以下のようになります(UNIX系の場合)。

```
> cat DISKROM64K.BIN IMAGE.DSK > IMAGE.ROM
```

このファイルをX68000に持っていき、以下のように起動します。

```
> ms.x -r IMAGE.ROM,A8K
```

すごいですね。複数枚のディスクが使えるとさらに便利なので、将来のバージョンアップを期待してしまいます。

## ms.iniファイルの詳細
BIOSROM、DISK BIOS、ディスクイメージ、カートリッジROMの指定などを `ms.ini` ファイルに書いておくことができます。
`ms.ini` ファイルは **カレントディレクトリ** から読み込みますので、例えば、ゲームのROMイメージがあるディレクトリに `ms.ini` ファイルを置いておくと、そのディレクトリで `ms.x` を実行するだけで、自動的に設定が読み込まれる、といった使い方が可能です。

ms.iniファイルの書式は以下のとおりです。最低限、mainromとsubromの指定がないと起動できませんのでご注意ください。

```
mainrom=MY_MAINROM.ROM
subrom=MY_SUBROM.ROM
diskrom=MY_DISKROM.ROM
kanjibasic=fs-a1f_kanjibasic.rom
kanjirom=fs-a1f_kanjifont.rom
cart1=GAME1.ROM
cart2=OTHER.ROM
; ディスクイメージを最大9個まで指定できます(書いた順番にセットされます)
diskimage=DISKIMAGE1.DSK
diskimage=DISKIMAGE2.DSK
diskimage=DISKIMAGE3.DSK
```

行頭を `;` もしくは `#` にするとその行はコメントとして扱われます。

### 上級者向け機能

普段使うことはあまりないですが、特定のスロットの特定のページに16KBのROMイメージを配置したい場合は、ms.iniに以下のように書くことができます。

```
slot1-1=ROM1.ROM
slot1-2=ROM2.ROM
```

これは起動オプションの `-r11 ROM1.ROM -r12 ROM2.ROM` と同じ意味になります。

### セーフモード

ms.iniを読み込まずに起動したい場合は、 --safe オプションをつけてください。その他のオプションは有効です。

```
> ms.x --safe
```

```
> ms.x --safe -r GAME.ROM
```

## 起動後の操作

* HELPキー
	* テキストプレーンに表示されているデバッグメッセージの表示/非表示を切り替えます
* SHIFT + CURSOR
	* テキストプレーンに表示されているデバッグ画面のスクロールができます
* 登録キー
	* MS.X の動作を一時停止します。もう一度押すと再開します。(再開がうまくいかないこともあるかもしれません)
	* 一時停止中に [RET] キーを押すとMS.Xが終了します
* 記号キー
	* デバッグ情報を出力します (HELPキーでデバッグ表示をONにしてください)
* OPT.1 + 数字キー
	* ドライブ1のディスクイメージの切り替えを行います
* OPT.2 + 数字キー
	* ドライブ2のディスクイメージの切り替えを行います(TODO まだ未実装です)
* F6キー
	* ms_debug.x を使っている場合のみ有効です
	* F6キーを押すと、ログレベルが上がります
	* SHIFT + F6キーを押すと、ログレベルが下がります
* F7キー
	* F7 + ESCで PSG/SCCのON/OFFを切り替えます
	+ F7 + 1,2,3,4,5,6,7 で、パートごとのON/OFFも可能です
		* 1: PSG CH1
		* 2: PSG CH2
		* 3: PSG CH3
		* 4: SCC CH1
		* 5: SCC CH2
		* 6: SCC CH3
		* 7: SCC CH4

# その他の調整

## ジョイスティックの設定

X68000とMSXは両者ともいわゆる「アタリ仕様ジョイスティック」と呼ばれるD-SUB9ピンのジョイスティック端子を持っています。両者は完全に互換性があるわけではありませんが、デフォルトでは両者のDSUB 9ピンが極力電気的に一致するようにマッピングしています。

ですので、(あまり試せてはいませんが)MSXのソフトで 8番ピンを使った特殊なデバイスもそのまま動く可能性があります(もしかしたらMSXマウスとかも動くかも?)

しかし、それでは都合が悪い場合は以下のような設定変更をこなうことも可能です。

### A/Bボタンを入れ替える

A/Bボタンの意味を入れ替えたい場合は、以下のようにして入れ替えが可能です。

```
【コマンドラインオプション】
> ms.x --joystick.swapAB
```

コマンドラインオプションの指定がない場合は、`ms.ini` の設定を見にいきます。

```
【ms.ini】
joystick.swapAB=true
```

いずれの設定もない場合は、通常動作します。

### ジョイスティックの入力にIOCSコールを使うようにする

デフォルトでは 8255のI/Oを直接叩いていますが、JOYDRV.xなどを使って連射やボタンの入れ替えなどを行いたい場合は、以下のようにしてIOCSコールを使うように設定してください。

```
【コマンドラインオプション】
> ms.x --joystick.useiocs
```

コマンドラインオプションの指定がない場合は、`ms.ini` の設定を見にいきます。

```
【ms.ini】
joystick.useiocs=true
```

## PAC (Pana Amusement Cartridge, Panasoft SW-M001) のサポート

SRAMバックアップ機能を持つ PAC を有効にすると、ゲームのセーブデータの保存に使用することができます(FM-PACはまだ未対応)。
たとえば、Ys IIはセーブデータをディスクもしくはPACに保存することができますが、ディスクの場合はいちいちディスクの入れ替えが必要なのに対し、PACの場合はディスクの入れ替えが不要なので便利です。

PACを有効にしたい場合は、exeフォルダの下にある `MSX.PAC` ファイルをカートリッジスロットにアタッチしてください。

```
> ms.x -r1 MSX.PAC
```

ms.iniファイルでも指定可能です。

```
cart1=MSX.PAC
diskimage=YS2_A.DSK
diskimage=YS2_B.DSK
```

PACに書き込まれたデータは、以下のタイミングでファイルに書き出されます。

* SHIFTキーを押しながら登録キーを押してポーズした時
* MS.Xを正常終了した時(登録キー2回押し)
* PACのSRAMが無効化された場合（ゲームによっては発生しません）

.PACファイルは、FM-PACのコピー機能でファイルに書き出されるファルと同じ形式です。そのため、実際の FM-PACのファイルツールで読み書きすることもできるはずです(持っていないので未検証)。また、他のエミュレータでも .PAC形式をサポートしているものであれば、読み書きできる可能性があります。

## ESE-RAM, ESE-SCC のサポート

実験的に、ESE-RAMと ESE-SCCをサポートしてみました。イメージファイルを DQ3_SCC.SRAM とした場合、以下のようにして起動します。

```
> ms.x -r DQ3_SCC.SRAM,ESCC
```

ms.iniファイルでも指定可能です。

```
cart1=DQ3_SCC.SRAM,ESCC
```

SRAMを書き換えた場合、以下のタイミングで SRAMファイルに書き出されます。必要に応じてバックアップファイルを用意しておくようにしてください。

* SHIFTキーを押しながら登録キーを押してポーズした時
* MS.Xを正常終了した時(登録キー2回押し)

## 擬似SCC音源の無効化

MS.Xでは、X68000の FM音源(OPM, YM2151) の8chの音を以下のように割り当てています。

* CH1: PSGのチャンネル1
* CH2: PSGのチャンネル2
* CH3: PSGのチャンネル3
* CH8: PSGのノイズ

ここで使用していない CH4,5,6,7 は、SCC音源のCH1,2,3,4 として割り当て、簡易的に音が出るようにしています。
SCCは CH5までありますが、CH5は鳴りません。また、波形メモリも一切見ていないので、非常にしょぼい音が出ます。

一応、PSGとは違う「SCCっぽい音」が割り当てられていますが、もし気に入らない場合は `--disablescc` オプションを指定してください。

```
> ms.x --disablescc
```

`--disablescc` には 0から 15の値を指定することができ、ビットパターンで、SCCの音を出すチャンネルを指定することができます。

* bit0: CH1
* bit1: CH2
* bit2: CH3
* bit3: CH4

のようになっています。たとえば、CH1とCH3の音だけを出したい場合は以下のようにします。

```
> ms.x --disablescc=5
```

0を指定した場合は、SCC音源を完全に無効にします。 `--disablescc` オプションは `--disablescc=0` と等価です。


この設定は、`ms.ini` ファイルに書くこともできます。

```
; SCC自体を無効にする場合
disablescc
; SCCのCH1とCH3の音だけを出す場合
disablescc=5
```

# チューニング

無調整で動けばいいのですが、実際にはいろいろな制約があり、チューニングが必要です。
「動かないゲームがある」「動くけどやたらと遅い」「途中で止まる」などの症状がある場合は、以下を試してみてください。

## CPUを早くする

X68000側のCPUが遅いと、あらゆる不具合が起きやすくなります。
MSXのソフトは、Z80 (3.58MHz) と VDPが一定の速度で動くことを前提としていますが、MS.Xはそれらをソフトウェアでエミュレートしているため、X68000のCPUが遅いと処理が間に合わず、ソフトが想定していないシチュエーションに陥ることがあります。

一番多いのは、1/60秒ごとのVSYNC割り込みの処理が間に合わない場合です。1/60で処理できるZ80の命令数はほぼ固定されているので、実機でギリギリ間に合うように作られているソフトなどが危ないです。エミュレーションが遅いと、次のVSYNC割り込みがかかるまでに前の割り込みが終わらないため、画面が乱れたり、時には暴走してしまったりします。

## VSYNC割り込みの周期を半分にする

```
> ms --vsrate 2
```

とすると、VSYNC割り込みが2回に一回しかかからなくなります。これにより、VSYNC割り込みの処理が半分になるため、CPUが遅い場合でも動作できる場合があります。ただ、特にゲームの場合は動作が半分になるのであまり嬉しくはありません。

## 自動フレームレート調整を使う/使わない

```
> ms --framecon auto
```

とすると、割り込み処理が終わらなかった場合に、次のVSYNC割り込みをスキップしてくれます。現在はこれがデフォルトの動作なので、明示的に指定する必要はありません。

一方、この機能がうまく働かないゲームもあるようです。割り込み処理が終わったことを検出できない場合に、必要以上にスキップしてしまうようなケースです。たいして重そうなゲームに見えないのに、やたらと動作が遅い場合は、以下のようにして自動フレームレート調整を無効にしてみてください。

```
> ms --framecon none
```

## フレームレート調整を細かく指定する

細かい説明は難しいのですが、 `--framecon` に 3000〜6000くらいの数字を入れると、うまく動くケースもあります。

```
> ms --framecon 4000
```

この数字は「次のVSYNC割り込みをかけるまでに保証するZ80の命令数」となっています。Z80の平均クロック数を10とすると、3.58MHzで1秒間に35万8000回の命令が実行されることになります。1/60秒だと約6000回の命令が実行されます。実機のMSXであれば大体このくらいの命令はこなせるはずなのですが、MS.Xは先述の理由により2000とかになってしまうケースがあります。そうすると、本来1/60のうちにやり切らないといけない処理がこなせないまま次のVSYNC割り込みが発生してしまい、誤動作することがあります。

命令数を保証することで、割り込みをスキップする代わりに、処理はやり切ることができるようになります。

ただ、数字を大きくし過ぎたりすると、`--vsrate 2` を指定しているのと大差ないことになりますので、絶妙な数字を見つけることができると、「そこまで処理落ちしないけど誤動作もしない」というポイントを見つけられることがあります。

上記方法でうまくいかない場合の奥の手として使ってください。


## ウェイトの調整

Phantom Xなど、高速なアクセラレータを使っていると、MS.Xの動作が速くなりすぎる場合があります。

通常のゲームは VSYNC割り込みで同期しているのであまり問題になりませんが、動作が早すぎる場合は以下のようにして、ウェイトを入れることができます。

```
> ms.x -w 100
```

この数字を大きくするとなります。

ウェイトの調整は `ms.ini` ファイルにも書くことができます。

```
cpu_wait=10
```

# 制限

いっぱいあります。

* 遅い
	* 画面の書き換えをまだチューニングしていないので、画面書き換えの多いゲームは動作が重くなる傾向があります。後々改善予定です。
* 速い
	* 逆に、画面の書き換えが少ないゲームは、実機よりも速く動作することがあります
	* CPUサイクルを数えて速度調整を入れるようにはしていますが、フィードバック方式でウェイトを入れているだけなので、動作にムラがあります。
* 落ちる
	* 不意にクラッシュしたり止まったりすることがあります
	* アプリがクラッシュすると、割り込み処理が登録されたままになり、その後の動作が不安定になることが多いです。そういった場合は X68000を再起動してください
* 再現性が低い
	* まだまだですね……
	* 拡大スプライトは途中まで実装していますが、まだ未対応です(あまり使っているゲームはなさそうですが)
* サポートしていないメガロムがある
	* まだまだいろんな種類があるようです
	* SRAM内蔵タイプなどもサポートしていませんが、そのうちしたいです
* FDDが(ちゃんと)使えない
	* 一応、読み込み/書き込み/フォーマットはできるようになりましたが、まだ不安定な感じがします
* サウンドの再現度
	* PSGのエンベロープ以外は再現度が上がりましたが、エンベロープを使っているものは未対応です
	* 正体的には FM音源や SSGもサポートしたいですが、Kepler Xなどの外部ハードを使うかもしれません
